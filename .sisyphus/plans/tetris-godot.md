## Context

### Original Request
User wants to learn Godot game development by building a modern full-featured Tetris clone. They know Godot basics (scenes, nodes, GDScript fundamentals) and prefer a guided implementation approach — learning by building with references to docs.

### Interview Summary
**Key Discussions**:
- **Scope**: Modern full-featured Tetris — SRS rotation, wall kicks, 7-bag randomizer, ghost piece, hold piece, 3-piece next preview, hard/soft drop, scoring with T-spins, level progression
- **Visual style**: Pixel art blocks generated by a Python script (32×32 per block)
- **Audio**: Sound effects only (no music)
- **Testing**: GUT (Godot Unit Test) framework for grid logic, rotation, scoring
- **Exclusions**: No multiplayer, no persistence/saves, no mobile/touch controls

**Research Findings**:
- **DON'T use TileMapLayer** — it's for static level design, not dynamic gameplay grids
- **Use 2D array** for grid logic + Node2D/`_draw()` for rendering (separation of concerns)
- **Timer vs _process(delta)**: Use `_process(delta)` with gravity accumulator for natural >1G handling at high levels
- **Pixel art settings**: Viewport stretch mode, Nearest texture filter, snap 2D transforms to pixel
- **SRS data**: Complete wall kick tables obtained for JLSTZ (shared) and I-piece (separate), verified against tetris.wiki
- **Scoring**: Full guideline table obtained — Single=100×level through T-Spin Triple=1600×level, with back-to-back and combo multipliers

### Metis Review
**Identified Gaps** (addressed):
- **Base resolution too narrow**: 320×640 leaves no room for hold/next/score sidebars → Fixed to **480×640** (80px left for hold, 320px center for playfield, 80px right for next+stats)
- **Buffer zone missing**: Grid must be 10×24 (20 visible + 4 hidden spawn buffer), not just 10×20
- **Gravity at high levels**: Timer node breaks above 1G → Using `_process(delta)` accumulator pattern instead
- **Coordinate convention**: SRS uses Y-positive=up but Godot uses Y-positive=down → Must negate Y values in wall kick tables
- **O-piece rotation**: Skip entirely (all 4 states look identical, simplest correct approach)
- **Game over timing**: Check AFTER line clears, not before (a piece can lock above row 20 but if it clears lines that bring the stack down, the game continues)
- **Lock delay edge cases**: Soft drop during lock delay should NOT reset move counter; hold piece resets rotation to state 0
